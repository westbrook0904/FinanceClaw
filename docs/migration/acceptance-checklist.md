# AgentScope Java 迁移验收清单

日期：2026-10-14。配套[迁移方案](agentscope-java-migration.md)。**M0 已完成本地验证，M1–M6 尚未实现/验收**；结果与边界见 [M0 验证记录](m0-validation.md)。

## 1. 如何记录证据

每项至少记录目标 commit、依赖版本、测试输入/环境、预期、实际结果和日志/报告位置。真实凭据只通过环境或密钥管理注入；报告不保存 token、个人原文和模型推理。

| 证据类型 | 可以证明 | 不能替代 |
| --- | --- | --- |
| 静态审查 | 文件、接口和配置的声明一致 | Java 编译、运行或恢复 |
| 单元 / 契约测试 | 固定输入下的业务规则和序列化 | 真实数据库竞争、SDK 网络行为 |
| 模拟集成 | 确定性模型、假 MCP、假飞书下的完整调用链 | 供应商质量、真实租户 UI 与回调 |
| 数据库 / 故障测试 | 事务、并发、持久恢复和去重 | 不同外部供应商的副作用语义 |
| 真实环境验收 | 指定版本、环境及场景的实际连接和结果 | 未覆盖场景、生产负载和长期稳定性 |

不要求 Java 与 Python 的模型自然语言逐字一致。确定性算法、授权、接口状态、数据归属和副作用次数必须符合冻结契约；模型回答按事实完整性、来源、工具选择和限制披露评估。

## 3. M1：业务生命周期

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| T01 | 相同身份、会话、幂等键和请求重复提交 | 返回同一受理结果，不新增业务任务或重复外部效果 |
| T02 | 相同幂等键，正文不同 | 明确冲突，不复用旧结果冒充新请求 |
| T03 | 同一 Conversation 并发受理两个活动 Turn | 保持单活动任务约束；不同会话可并行 |
| T04 | API 受理后、Worker 领取前重启 | Command 保留，可继续执行，不丢任务 |
| T05 | Worker 领取后异常退出 | 租约/attempt 可核对；旧 Worker 迟到写入无效 |
| T06 | SSE 断连、重连、重复游标 | 任务继续；快照 revision 单调；不重新运行 Agent |
| T07 | 模型返回文本但存在待审批/待工具 | 不标记 completed |
| T08 | 状态已保存，业务完成事务前退出 | 按原 attempt 幂等补交 Journal/Outbox，不再执行整条任务 |
| T09 | 取消与最终结果同时到达 | 由已定义的事务/CAS 规则得出唯一终态，不产生相互矛盾通知 |
| T10 | 终态后收到旧模型片段、旧工具事件 | 不覆盖终态和新 Turn 卡片 |
| T11 | API、Worker、Integrations 多副本 | 幂等领取与投影，不依赖单进程锁 |
| T12 | 失败/取消后新建 Turn | 使用符合隔离规则的干净执行状态，合法历史 Journal 仍可读 |

- [ ] T01–T12 均有可重复证据；其中并发与崩溃测试使用真实 PostgreSQL。
- [ ] `/health/ready` 等价能力检查数据库、迁移、运行状态存储和 Artifact 等必需依赖；进程存活不冒充服务就绪。
- [ ] 数据库、模型、对象存储、SSE 的超时/连接池/线程边界有配置并能取消或回收。

## 4. M2：授权、交互、上下文与工具

- [ ] 相同 subject 名称但不同 tenant、相同会话 ID 但不同 Agent/发布均不能读写对方状态。
- [ ] 身份、授权范围和执行时钟由服务端注入，模型不能通过工具参数自行修改。
- [ ] 发布在受理后更新，正在运行/恢复的 Turn 仍使用固定发布；版本不可用时明确阻断。
- [ ] 审批校验 action hash、工具参数、问题 revision、有效期、状态版本和当前 Turn。
- [ ] 重复正确回答幂等；错误类型、旧卡片、已取消任务、已撤销授权和其他用户回答均被拒绝。
- [ ] 子 Agent、Workflow 和 MCP 全部经过相同治理端口；权限及预算只能收窄。
- [ ] 模型/工具重试按故障分类；只读瞬时失败可有界重试，写操作有幂等/核对策略。
- [ ] 超长酒店结果、中文、多模态块、tool calls、response schema 和大量工具定义进入完整请求预算测试。
- [ ] tokenizer 缺失时的保守估算单独通过，Java 不依赖 Python tiktoken 缓存。
- [ ] 必需上下文超限时，在模型调用之前失败；没有通过丢弃原始用户请求或放大预算逃避失败。
- [ ] 降级模型使用其实际窗口与参数；Qwen thinking、无正文响应和 usage 异常有明确结果。
- [ ] Artifact 完整结果 hash 可查；引用和回读有大小限制，列表分页正确，JSON 对象不被列表切片。
- [ ] 工具进度只暴露固定工具名和状态；日志/卡片无参数、原始结果、异常正文或推理内容。

## 5. M3：MCP、Skills、子 Agent 与 Workflow

| 场景 | 必测输入 / 故障 | 通过标准 |
| --- | --- | --- |
| 酒店 MCP | 查询、详情、标签；大数组；超时；契约变化 | 权限/host/预算正确；引用可授权回读；输入结构漂移拒绝执行 |
| MCP 注释变化 | 仅 title/description/example/default 变化 | 不产生错误的契约漂移阻断 |
| MCP 业务字段 | 参数名为 description；enum/const 内有同名字段 | 规范化不破坏业务数据 |
| 禁用 MCP | 未提供密钥或契约文件 | 不初始化该服务，不影响其他启用能力 |
| Taibu | 固定 almanac / bazi 输入及服务错误 | 业务 schema、错误分类、数据级别与 host 校验一致 |
| 调酒 Skill | `/skill` 显式选择、按需资源、重复激活 | 方法正确加载；身份/版本/hash 验证；不污染用户事实 |
| Skill 失败 | 超限、撤销、资源越界、并行依赖工具 | 激活状态不部分提交；无越权读取；独占加载规则有效 |
| 市场研究子 Agent | 正常研究、缺资料、失败、超预算 | 父子状态隔离；根层澄清；共享预算；来源与时间可解释 |
| 投资组合 Workflow | 中途审批、重复恢复、步骤失败 | 固定步骤可恢复；每步效果有账本；不跳过审批 |
| 紫微可选能力 | 五类排盘、历法、时区、日期范围、资料缺失 | 与冻结算法基准一致；不猜用户资料；不把未验收能力标为生产可用 |

- [ ] 所有启用场景都有模拟集成；酒店/调酒/子 Agent 展示可由文档复现。
- [ ] 子任务与根任务即使生成同名 call ID，进度和账本也不会合并错位。
- [ ] Skill 正文不在持久对话、Journal、记忆来源中出现；恢复时会重新授权，撤销后 Artifact 也不能绕过。
- [ ] 固定文本资产的许可证和 SOURCE 信息随迁移保留。

## 6. M4：记忆和飞书

- [ ] 记忆仅来源于可信、同主体、真实用户证据；模型、工具、Skill 文本不能写成用户事实。
- [ ] 低风险偏好与需确认候选的处理分别测试；记忆确认不误恢复业务 Interaction。
- [ ] 提取/整合重复消费幂等，模型失败不丢 Outbox；索引故障可重试且不改写事实。
- [ ] owner/revision/privacy epoch 校验覆盖读取、搜索、索引重试、恢复与重建。
- [ ] 遗忘发生后，迟到索引写入、旧候选和缓存不能使内容复活；需要持续清理的状态有可观测结果。
- [ ] 供应商输出维度、配置、列类型和索引一致；更换 embedding 模型有明确重建版本。
- [ ] Memory Worker 通过受限数据库身份测试，不能读取不需要的业务数据或调用业务工具。
- [ ] 飞书重复事件不会启动重复任务；渠道身份绑定、静音、切换 Turn、旧卡片回调均正确。
- [ ] 飞书流式卡片、工具进度、文本澄清、表单回答、审批、取消与最终正文都覆盖。
- [ ] 通知投递未知结果按业务事件 ID 核对，不为重试创建新的逻辑通知。
- [ ] 真实租户验收与模拟飞书测试分开记录。
