# 整轮对话的数据库访问基线：P3a.8

**状态：2026-10-25 已推送 `f330a17`，远程流水线通过。** 前置提交 `c166da7` 已推送，GitHub [run 40157422639](https://github.com/westbrook0904/FinanceClaw/actions/runs/40157422639) 整体成功：1,750 项 Java、46 项脚本、44 项部署检查。该远程基线与本阶段新增测量分别记录。

## 目标与范围

先建立整轮数据库成本基线，为发布查询、Worker 领取、通知投递和上下文持久化的后续优化提供依据。本阶段新增测试观察与证据归档，不调整生产权限、租约、隐私、预算、认证或执行逻辑。

1. 普通对话：真实 HTTP 受理、自动 Worker、AgentScope 和本机 OpenAI SSE 协议服务，观察一次无工具 Turn。
2. 行情父子调用：相同生产链路，验证冻结行情目标、根/子模型与工具计数以及完整持久化成本。
3. 双 owner 并发：同一业务 Spring 上下文，两个 owner 各两个会话，经真实应用服务并发受理，由正常 Worker 执行；核对上下文、结果和预算隔离。当前 HTTP Bearer 只映射一个服务端主体，本场景不证明多用户 HTTP 认证。

## 测量与验收约束

- 新增测试专用的全线程 JDBC 窗口，保留 P3a.7 的线程内计数器及原始证据。借连接时捕获窗口，窗口前已借出的连接可在首次 SQL 时绑定；等待同一逻辑连接的 SQL、事务结束和归还，不把在途工作记入下个样本。
- 窗口从受理前开始，到已提交终态后排空已绑定连接。发布、创建会话及断言使用非计数连接；观察成本和排除项须明确记录。
- 保留窗口内全部应用 SQL，按模板摘要、线程来源和语句类别分别统计后台扫描、心跳与执行工作。并发报告整批成本，不伪造逐 owner 的共享 SQL 分摊。
- 不记录原 SQL、绑定参数、用户正文或模型提示词。JDBC 调用次数不等于数据库网络往返；连接借用调用耗时不等于纯连接池排队，SQL 调用耗时不等于数据库锁等待。
- 原始测量输出 `target/p3a8/turn-sql-baseline.json`，CI 同时归档 `target/p3*/`。计数器跨线程、排空、异常和容量边界须有独立测试，场景须核对真实持久事实。
- 使用隔离 PostgreSQL、本机模型协议服务和当前应用类；不宣称真实模型质量、独立打包 JAR 父子链路、生产吞吐或容量已达标。

## 实测结果

本机 PostgreSQL 16.10、Worker 并行度 4、业务连接池上限 8。为在有限时间内建立事件订阅并观察续租，fixture 的领取 tick 与空闲上限均为 100 ms、心跳为 1 s、租约为 60 s；生产默认分别为 250 ms／5 s、2 s、15 s。下表包含该测试窗口内的后台工作，不能外推生产稳态扫描量、吞吐或响应分位数。

| 观察窗口 | 应用 SQL 总数 | 发布清单查询 | 领取候选查询 | 过期扫描 | 心跳续期 | 工作投影 UPSERT | 显式提交 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 普通 HTTP 对话，1 Turn | 134 | 36 | 8 | 1 | 1 | 1 | 19 |
| 行情父子 HTTP 调用，1 Turn | 380 | 144 | 27 | 2 | 2 | 1 | 52 |
| 双 owner 四会话并发，整批 | 508 | 144 | 5 | 2 | 5 | 4 | 50 |

发布查询包括 legacy/v2/v3 格式探测与基础发布读取，三个窗口分别为 `18+9+9`、`72+36+36`、`72+36+36`。全部 SQL 执行成功，显式回滚及提交/回滚失败均为 0；连接借用调用分别为 31、73、96 次，均成功。原始测量保留固定线程来源、模板摘要、SQL 调用耗时与完整借连接调用耗时。

窗口内另外排除 1、1、8 次观察查询。报告中的 82 次总观察查询还包含窗口外的核查与清理探针，不是全部 fixture 初始化语句。观察连接绕过计数器，但仍使用同一真实连接池，因此它们也会产生资源开销。完成依据是生产事件中心的提交后终态，再等待已绑定逻辑连接归还；没有用模型返回或持续 HTTP 状态轮询代替业务提交。

普通 Turn 实际消耗 1 次模型、0 次工具；行情 Turn 根预算为 4 次模型／2 次工具，子调用为 2／1，行情来源是冻结目标；并发批次四个 Turn 各消耗 1／0。四个模型 gate 同时进入，且核对四个具体 attempt 的已提交租约确实延长；5 次心跳 SQL 不能被解释为五个任务。画像、问题、回答、Agent/release 和工作投影均逐个验证隔离。

## 后续热点排序（建立基线时）

1. **先合并发布解析。** 普通 Turn 已有 36 次发布查询，行情链路达到 144 次。下一步应减少每次不可变清单解析中的格式探测与基础读取，保留 owner、内容摘要、当前 grant、隐私和租约检查；本阶段没有预设可减少多少比例。
2. **再测领取与渠道投递。** 本报告包含领取和过期扫描，可作为 Worker 查询改动的参照。飞书在本 fixture 中关闭，其提交唤醒、逐绑定投影与有界批处理仍需独立基线，不能用这三个窗口认证。
3. **长工具链再测上下文写入字节。** 本次每 Turn 只有一次根工作投影 UPSERT，未证明轨迹重写是当前主要成本；长 Turn 的正文大小、写入放大和数据库锁等待仍待专门测量。

共享连接池下的生产容量、更多 owner 的公平性、真实模型与 MCP 限流，以及独立应用 JAR 的新增行情父子链路验收继续单独推进。
