## 优化范围

每次模型或工具扣额都先检查固定发布、执行租约、Turn 状态、用户隐私和当前 grant，再预留子额度与扣减根额度。此前 `consume` 在检查发布时解析一次，扣减根额度前又解析一次。MyBatis 使用 `local-cache-scope=STATEMENT`，第二次解析会再次访问数据库。

本模块将第一次核验得到的不可变 `ExecutionPolicy` 保存在本次回调内的私有 `CheckedPolicy` 中，根预算直接使用该投影。它不会成为公开句柄，也不保存到字段、ThreadLocal、检查点或其他事务。后续调用仍重新解析自己的固定发布。

权限快照、grant、隐私 epoch、调用计数和租约均不复用。嵌套调用仍进入原门禁，因为持有命令行锁期间，数据库时间仍可能使租约过期。`effectiveScopes` 和行情目录的其他查询保留，回放也必须先经过实时门禁。

生产改动限定在 `ExecutionPolicyService`，不改变公开方法、表结构、Worker 调度、轮询、SDK 检查点或网络调用边界。权限检查、子额度预留、根预算 CAS 的顺序保持；失败仍整体回滚。

## 运行工件与剩余热点

生产 class 变化会改变运行工件摘要。既有组合发布仍受 `RuntimeArtifacts` 守卫约束，本次优化不添加旧发布兼容路径，也不自动重绑定暂停执行。

本模块只消除同一次预算扣减中的第二次根发布解析。父子行情调用的内外租约、隐私、权限检查以及 `effectiveScopes` 的发布解析仍保留；没有认证整条 Turn 的数据库降幅、吞吐或生产容量。独立打包 JAR 的新增行情父子链路验收仍是后续工作。
