# 应用运行结构

HTTP API、AgentScope 执行、任务恢复、SSE 和飞书投递运行在同一个 JVM，共享业务连接池和进程内事件中心。项目是单个 Maven 应用，不提供旧的 API/Worker/Integrations 分体 profile。

| 服务或入口 | 用途 |
| --- | --- |
| Compose `api`，入口 `standalone` | 统一业务进程 |
| `memory-worker` | 记忆提取、索引和清理，使用受限数据库身份 |
| `init-db` | 新库结构初始化与授权，完成后退出 |
| `privacy-recovery` | 停写隔离环境中的遗忘事实初始化与恢复重放 |
| `postgres` | 权威业务状态、结果和记忆事实 |

实时 SSE 先订阅进程内事件，再读取游标之后的持久事件，并按修订号去重。只在检测到修订号缺口时补读；空闲心跳不查询数据库。连接数量、缓冲区和时长受限，连接结束不表示业务任务完成。

当前支持一个业务 JVM 中的多用户与多会话并行执行。生产认证需接入可信身份源；默认 Bearer 配置映射一个主体，不能由请求正文选择用户。当前没有跨实例事件总线，部署时保持一个业务副本。

Worker 使用提交后的进程内通知唤醒，以最长五秒空闲退避扫描兜底。过期执行单独恢复，心跳使用专用调度器。调度线程隔离不能消除数据库争用，续租仍依赖共享连接池、语句超时和不可复活的租约校验。

启动见[新库初始化](fresh-schema.md)。常规停写：

```bash
docker compose stop api memory-worker
```

数据库备份恢复、旧备份的隐私核对和独立遗忘事实重放是当前应用的安全运行需求，继续保留。操作入口见[运行维护](../operations.md)，不得让业务进程连接未经隐私核对的恢复库。
