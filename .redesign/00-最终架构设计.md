# FinanceClaw 最终架构设计

状态：Accepted

## 1. 架构目标

FinanceClaw 不再定位为通用 Agent Framework。目标产品是一个建立在 LangChain、LangGraph Agent Server 与 LangSmith 之上的金融 Agent 应用平台，其差异化集中在：

- 可追溯的多轮会话与长期记忆；
- 金融数据的新鲜度、来源和证据约束；
- Tool 的身份、权限、side effect、幂等、egress 和审批；
- 确定性金融 Workflow；
- 完整的金融 Audit 与可评测闭环。

## 2. 总体架构

```text
Client
  │ OIDC/JWT + idempotency key
  ▼
FinanceClaw API / BFF
  ├─ Authentication / tenant ownership
  ├─ Conversation Journal
  ├─ Target resolution
  ├─ Domain Request/Response
  ├─ Approval API
  ├─ Financial Audit / Outbox
  └─ Agent Server stream projection
          │ internal service auth
          ▼
LangGraph Agent Server
  ├─ finance_agent             默认顶层 Agent
  ├─ direct_tool               显式单 Tool 调用
  ├─ published workflows       固定、版本化 StateGraph
  ├─ assistants / threads / runs
  ├─ checkpoint / store
  ├─ queue workers / streaming
  └─ interrupt / resume
          │
          ├─ LangChain Models / Middleware
          ├─ LangChain BaseTool / MCP Tools
          ├─ Financial Services
          └─ PostgreSQL / Redis / Artifact Store

LangSmith
  └─ Agent / Workflow / Model / Tool / Middleware Trace 与 Evaluation
```

## 3. 顶层请求分派

分派完全由显式 Target 决定，不调用 LLM：

```text
RunRequest
  ├─ ToolTarget      → direct_tool graph
  ├─ WorkflowTarget  → published workflow graph
  ├─ AgentTarget     → specified AgentProfile
  └─ no target       → default finance_agent
```

不再存在：

- FAST/PLAN/REACT 运行模式；
- LLM Router 或 LLM ModelSelector；
- 在线复杂 PlanDraft；
- 运行时动态生成 Workflow DAG；
- Planner 与 Explorer 两套独立上下文消费者。

顶层默认 Agent 可以使用标准 Tool Calling 进行多步探索；需要重复、可验证和可审批的流程必须固化为 Workflow。

## 4. Agent、Workflow 与 Tool

### 4.1 Agent

第一阶段只发布一个默认 `finance_agent`。它由 LangChain `create_agent` 构建，运行在 LangGraph 上。AgentProfile 只负责版本化配置：

- ModelProfile；
- system prompt template；
- Tool allowlist；
- Middleware profile；
- Context/Memory policy；
- model/tool call limits。

Conversation 创建时固定 AgentProfile 版本；升级必须显式迁移。

### 4.2 Workflow

Workflow 是代码定义、测试通过并发布的 `CompiledStateGraph`。每个 Workflow 必须有：

- 稳定 `workflow_id/version`；
- Pydantic 输入输出 Schema；
- 固定拓扑和显式条件边；
- 固定 Tool/Agent/Profile 版本；
- checkpoint、interrupt/resume 和失败语义；
- 契约、集成和 LangSmith 回归测试。

Agent 可作为 Workflow 节点或子图，但 Agent 不生成新的可执行 DAG。

### 4.3 Tool

Tool 的唯一运行时标准是 LangChain `BaseTool`。FinanceClaw 仅在其外维护治理元数据：

```text
ManagedTool = BaseTool + ToolGovernance
```

`ToolGovernance` 至少包含：

- `tool_id/version`；
- `side_effect`；
- `idempotency`；
- `risk_level`；
- `required_scopes`；
- `approval`；
- `egress`；
- `sensitivity`；
- `retry_profile`；
- `audit_level`。

LangChain 负责 Tool Schema、参数校验、调用、ToolMessage、retry 和 HITL 机制；FinanceClaw 的纯 Policy 函数负责 ALLOW/DENY/REQUIRE_APPROVAL 决策。

## 5. 模型层

模型直接使用 LangChain `BaseChatModel/init_chat_model` 和各 Provider Integration，不保留自研 `ModelRuntime/ModelProvider`。

`ModelProfile` 是配置和治理，不是协议适配：

- model/provider 标识；
- timeout、temperature、output budget；
- fallback profile 链；
- data classification/region；
- Tool Calling 与 structured output 能力。

Agent/Workflow 固定 ModelProfile。LangChain 执行 model retry/fallback；FinanceClaw 只确保 fallback 候选满足相同的数据和 egress 约束。

## 6. 会话、Context 与 Memory

### 6.1 Conversation Journal

所有用户消息和 Assistant 可见回复 append-only 永久保存，不设置自动 TTL。重新生成和分支通过 `parent_message_id` 建模，不覆盖原消息。

### 6.2 Prompt Context

模型上下文按每次 `model_call_id` 动态构建：

```text
P0 System / mandatory policy
P1 current user input
P2 current tool results / pending state
P3 recent raw conversation window
P4 stable long-term memory
P5 relevant segment/hierarchical summaries
P6 relevant older raw messages
P7 optional background
```

限制依据 token budget，而不是固定字符或消息条数。LangChain Middleware 负责组装、summarization 和 context editing；FinanceClaw 负责 provenance、trust、sensitivity、tenant 和金融数据新鲜度。

### 6.3 Summary

Summary 是可重建的派生索引，不替代原始对话。采用分段摘要、分层摘要与相关性召回的混合策略；每份摘要保存覆盖范围、来源 message IDs、模型/模板版本和 hash。

### 6.4 Long-term Memory

LangGraph Store 提供存储和检索机制；FinanceClaw `LongTermMemoryService` 提供领域治理。Memory 只保存 preference、goal、constraint、decision_note 等长期信息，使用 active/superseded/revoked/deleted 生命周期。

实时行情、持仓、余额、订单和可重新计算的风险指标不属于 Memory，必须通过金融 Tool 查询权威数据源。

## 7. 执行平面与产品 API

LangGraph Agent Server 是内部执行平面，负责 assistants、threads、runs、task queue、checkpoint、store、streaming 和 interrupt/resume。

FinanceClaw API/BFF 是唯一公网和业务安全入口，负责：

- OIDC/JWT 验证与可信 ExecutionContext；
- Conversation 所有权；
- Target 解析；
- 请求幂等；
- 领域 API 和 SSE 事件投影；
- Approval；
- Audit 与 Artifact；
- Agent Server 内部调用。

不在 BFF 中重建 Run 状态机、Graph Worker、队列或 checkpoint API。

## 8. 数据与基础设施

推荐同一 PostgreSQL 集群使用独立数据库：

```text
financeclaw_app    业务会话、摘要、Manifest、Approval、Audit、Artifact metadata
financeclaw_agent  Agent Server 的 assistants、threads、runs、checkpoint、store
```

Redis 供 Agent Server 队列与 Pub/Sub；大 Tool Result、报告和附件进入 S3 兼容 Artifact Store，Prompt 只注入摘要、引用和 hash。语义检索第一阶段使用 PostgreSQL/pgvector，不引入独立向量数据库。

## 9. 观测与审计

- LangSmith：Agent/Workflow/Model/Tool/Middleware 调用链、Prompt 调试与评测；
- OpenTelemetry：HTTP、PostgreSQL、Redis、外部 HTTP 等基础设施；
- Application Log：运行与调试日志；
- AuditRepository：永久的金融业务决策和行为记录；
- Outbox：确有外部可靠事件投递需求时使用。

开发环境 LangSmith 和本地日志记录完整 Prompt、Tool Schema、模型输入输出与 Tool I/O；生产按 tenant 和 data classification 做条件追踪、隐藏或脱敏。

## 10. 不再建设的能力

- 通用 Capability Framework；
- Agent/Tool/Plugin SPI；
- 动态 Provider Registry/Health/Priority Selection；
- 自研模型协议栈；
- 自研 ReAct Loop；
- 自研 DAG/Checkpoint/Resume；
- 通用 Policy Engine；
- Context Snapshot/Projection Runtime；
- Memory Provider/SQLite SPI；
- 自研 Trace/EventBus；
- 自研 Run/Thread/Queue/Stream Server；
- 在线复杂 PlanDraft。

## 11. 完成标准

最终重构完成时，主运行链只能由以下核心组成：

```text
FinanceClaw Domain API
  + LangChain Agent/Model/Tool/Middleware
  + LangGraph Agent Server/StateGraph/Store
  + LangSmith Trace/Evaluation
  + FinanceClaw Conversation/Memory/Tool Governance/Audit
```

任何与上述目标重复的旧 Harness Runtime 都必须删除，而不是长期保留为兼容层。
