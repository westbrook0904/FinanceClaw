# FinanceClaw 目标模块与依赖设计

## 1. 设计原则

- 以产品与领域边界组织模块，不再按通用 Harness 内核分包。
- LangChain/LangGraph 原生类型在运行时内部直接使用。
- API、持久化和 Audit 边界才定义稳定 FinanceClaw DTO。
- Catalog 是只读配置；Service 是领域规则；Middleware 是框架适配；Repository 是持久化边界。
- 不为测试方便引入生产抽象；框架已有 Fake/Stub 时优先复用。

## 3. 依赖方向

```text
api
  → application
      → agents / graphs
      → conversation / memory / tools / audit
          → infrastructure interfaces

infrastructure
  → implements repositories/clients

LangChain / LangGraph types
  → only inside agents, graphs, tools and middleware
```

禁止：

- Repository 依赖 FastAPI；
- 领域 Policy 依赖 Agent Server HTTP；
- Tool 直接信任 API body 中的 tenant；
- Conversation/Memory Contract 依赖旧 Capability Descriptor；
- Workflow 通过全局 mutable Registry 找 Tool；
- API 直接读写 Agent Server 内部数据库。

## 4. 核心对象

### 4.1 Request Target

```python
ToolTarget(tool_id, version=None)
WorkflowTarget(workflow_id, version=None)
AgentTarget(agent_id, version=None)
```

`TargetResolver` 只做确定性解析、版本选择和错误返回。

### 4.2 Profiles 与 Catalog

```text
ModelProfileCatalog     model profile → BaseChatModel factory input
ToolCatalog             tool id/version → ManagedTool
AgentCatalog            agent id/version → AgentProfile
WorkflowCatalog         workflow id/version → deployed graph/assistant
```

所有 Catalog 在进程启动时构建并冻结。配置更新通过发布新版本/部署完成，不在运行中热改。

### 4.3 ManagedTool

```python
ManagedTool
  tool: BaseTool
  governance: ToolGovernance
```

授权必须在两个位置执行：

1. `wrap_model_call` 前过滤模型可见 Tool；
2. `wrap_tool_call` 或 Workflow Node 执行前再次校验，防止仅依赖可见性。

### 4.4 ExecutionContext

```python
ExecutionContext
  tenant_id
  subject_id
  scopes
  conversation_id
  turn_id
  run_id
  data_classification
  locale
  timezone
```

它从认证后的请求构造，通过 LangChain/LangGraph Runtime Context 传播，对模型隐藏。

### 4.5 AgentProfile

```text
agent_id/version
model_profile
system_prompt_template
allowed_tool_ids
memory_policy
context_policy
middleware_profile
max_model_calls
max_tool_calls
```

第一阶段不建设多 Agent 调度框架；specialist Agent 只有在明确业务边界与评测数据存在时才增加。

### 4.6 WorkflowDefinition

```text
workflow_id/version
graph/assistant identifier
input/output schema
tool/profile version pins
approval policy
deployment revision
```

## 5. 框架适配面

只允许少量、单向的 Adapter：

- `ModelFactory`：ModelProfile → LangChain BaseChatModel；
- `AgentFactory`：AgentProfile + Catalog + Middleware → compiled agent；
- `MCPToolLoader`：MCP Tool → BaseTool + local governance overlay；
- `AgentServerClient`：产品 Run/Stream/Resume → Agent Server API；
- `StreamProjector`：LangGraph stream event → 产品 SSE event；
- `MessageMapper`：LangChain visible message ↔ ConversationMessage；
- `AuditMapper`：framework run metadata → AuditRecord refs。

不得出现大而全的 `FinanceClawRuntime`、`CapabilityInvoker` 或 `GraphRuntime` 包装器。

## 6. 配置与依赖

建议基础依赖类别：

- `langchain` 与实际使用的 provider packages；
- `langgraph`、Agent Server/CLI 相关包；
- `langchain-mcp-adapters`；
- `langsmith`；
- `fastapi`、ASGI server；
- `pydantic-settings`；
- `sqlalchemy`、`alembic`、PostgreSQL async driver；
- OpenTelemetry FastAPI/SQLAlchemy/HTTP instrumentation；
- 对象存储 SDK；
- `pytest`、`ruff` 与必要的 integration test 工具。

不预装所有模型或向量数据库 Provider；按实际启用范围最小化依赖。

## 7. 对外 Contract

只保留产品稳定边界：

- RunRequest/Target；
- Conversation/Turn/Message API；
- Agent/Workflow/DirectTool Response；
- Stream Event；
- Approval Request/Decision；
- Artifact Reference；
- 公开 Error Response。

内部直接使用 BaseMessage、ToolMessage、Command、Interrupt、RunnableConfig、StateGraph 和框架异常；不再复制其 Schema。

## 8. 生命周期

FinanceClaw API 生命周期只负责：

- settings/secret clients；
- application database pool；
- Agent Server client；
- MCP clients；
- LangSmith/OTel/logging；
- graceful shutdown。

Agent/Graph worker、checkpoint 和 run queue 生命周期交给 Agent Server。
