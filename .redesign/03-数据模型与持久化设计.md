# 当前持久化设计

业务库由 BFF 与 Agent Server 共享，并非全部属于 BFF。当前 Alembic `0001_initial` 与 ORM metadata 一致，共 **20 张表**。本次从 22 张减到 20 张；项目尚未上线，直接维护唯一初始 schema，不保留旧表升级链。

| 领域 | 表 | 保留理由 |
|---|---|---|
| 会话与上下文（6） | conversations、conversation_turns、conversation_messages、conversation_summaries、model_context_manifests、channel_conversation_bindings | 会话归属、每轮幂等、永久原文、可更新摘要、每次模型输入证据、渠道绑定各有不同唯一性和生命周期 |
| 执行（4） | run_executions、run_operations、root_runs、run_progress_events | 冻结发布与治理账本、每次 start/resume 的出站命令及回执、根状态及协调租约、可重放进度分别由不同职责读写 |
| 授权与恢复（3） | run_authorizations、pending_interactions、run_inbox | 有限授权、不可变问题与一次决定、后端唤醒及用户命令回执各有独立约束 |
| 制品与审计（3） | artifacts、audit_records、outbox_events | 对象元数据、不可变审计、审计外发投递责任不能由同一个“已发送”标志表达 |
| 通知（4） | notification_targets、notification_events、notification_deliveries、notification_senders | 每轮固定收件目标与卡片 ID、业务事务快照、网络投递及分片回执、发送进程心跳分别表达不同事实 |

## 本次整改

- **删除 `backend_attempts`**：每个固定 `run_operations.operation_id` 最多绑定一个远端回执，原表与操作表为一对一。把 `backend_instance_id`、`execution_hash`、完整 `reference` 合并到 `run_operations`，保留远端身份唯一索引、回执不可替换、早到回调关联和未知提交恢复。删除无消费者的 `cancellation_confirmed` 字段；停止确认仍由既有命令/根状态处理。
- **删除 `run_control`**：移除未上线部署使用的持久受理/派发门闩、CLI、服务分支和探针设置。BFF 就绪后直接受理。数据库租约、容量限制、epoch、授权检查和取消语义仍是执行正确性所需。
- **卡片不新增表**：`notification_targets` 保存卡片实例 ID、消息 ID、已确认序号及最新期望视图；`notification_events` 保存不可变视图，按钮只引用这个视图；`run_inbox` 保存渠道事件和语义操作的回执，决定与回执同事务。
- 删除通知 `delivery_mode`、未使用的 `content_version`、通知启用开关、旧前台流式回复与旧 attention/interaction 文本通知生成路径。卡片之外的最终长文本仍按 UTF-8 分片，这是内容交付能力。

未继续把剩余表合为一张大 JSON 表：例如根租约和执行发布快照虽然一对一，但前者属于 BFF 调度、后者由 Agent 工具治理共享；通知事件与投递是一对多，未知网络结果不能覆盖已提交的业务事实；摘要不能覆盖永久聊天原文。合并这些实体会弱化约束、扩大锁竞争或丢失证据，收益小于成本。

## 事务边界

一个业务 Turn 只有一个根执行，数据库约束 `root_run_id = run_id`。Worker 是根图内的子图，不创建独立业务任务。原生 start/resume 回执现在直接属于操作行。

BFF 受理同事务写 user Journal、Turn、发布快照、授权、start operation、Inbox、进度和首张卡片意图。完成核对同事务写操作观察、assistant Journal、Turn、进度、审计和通知意图。Webhook 只保存认证后的最小唤醒线索，不能成为最终答案。

卡片决定持有根锁，复验身份、视图、交互期限、Schema、动作摘要和授权，原子写决定、resume 或停止/授权控制、审计、Inbox 回执与新卡片快照。网络调用全部在事务外。CardKit 更新和最终文本各有固定 UUID，后者每片独立记录。

## 初始化与保留

对新空开发库执行 `alembic upgrade head`；测试使用可丢弃库验证 upgrade、metadata 差异和 downgrade。既有本机数据库不自动删除，也不能只因其 Alembic revision 同为 `0001_initial` 就认为列结构已更新。

Journal 原文与当前根投影长期保留；通知历史、命令回执和进度有不同保留需求。本次不增加自动删除业务证据的作业，回执上的期限不是自动删除授权。制品正文由 Artifact Store 保存；原生 Thread/Run/Checkpoint 与长期 Memory Store 由 Agent Server 部署负责。
