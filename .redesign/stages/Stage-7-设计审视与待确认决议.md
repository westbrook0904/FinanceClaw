## 1. 本轮审视结论

“一个领域子 Agent＋五个盘面工具＋确定性排盘服务”的方向适合当前项目。
主要问题不在 Agent 数量，而在计算口径、结果证据与已有委派链路的实际行为。

本轮是代码静态审视和设计整理，没有安装／运行候选引擎，没有完成生产恢复验证，
也没有批准默认流派或时间规则。不对基础设施完成度给出缺少测量依据的百分比。

## 2. 对前序讨论的修正

| 讨论中容易产生的误解 | 审视结论 | 本设计处理 |
|---|---|---|
| 加 Profile 和 Tool 即可落地 | 现有委派是文本输入／最终文本输出，结构化字段会丢失 | 明确 handoff v2、输入校验、最终 state 结果契约 |
| 日盘需要 Agent 连续获取五张盘 | 会增加调用和混用规则风险；层级是分析上下文，不必是五次计算依赖 | 服务原子生成到目标层级的快照 |
| 时而每次传出生资料，时而只能拿 chart_id 查询 | 两种契约混用会造成资料串用和前置调用隐患 | child 不可变出生上下文＋五个无前置依赖的门面；ID 仅追溯／授权读取 |
| 缺资料让子 Agent 直接 interrupt | 当前 Agent child 没有用户交互恢复闭环 | 返回 needs_clarification，根会话追问，新 Turn 重委派 |
| 配 `context_policy` 就实现隔离 | 当前 Factory 未按该字段限制子 Journal | 增加真实 task-only 策略与隔离测试 |
| Profile 和 Tool 写了版本就已锁定 | 实际 graph 与部分治理路径仍可能使用当前实现／latest | 服务端版本化 graph 绑定、一次性 Tool 解析和恢复快照 |
| READ 工具恢复可直接给 `*` | 只读也可能泄露跨用户资料，恢复扩权不成立 | 保存授权上界；未知权限失败或重新授权 |
| Artifact 有摘要就足够分析 | 摘要和 token 截断可能删除事实，当前没有通用回读工具 | 结构化语义投影＋完整 Artifact；不足显式失败 |
| 一个年份等于该年任意一天的流年盘 | 公历区间可能跨年界和大限 | TargetSelector 明确区间，按规则拆段 |
| `ageDivide` 就是大限年龄分界 | 不能从小限虚岁配置推出大限行为 | 分别列规则，分别验证大限与小限，后一项一期不暴露 |
| 两个有共同来源的库一致即绝对正确 | 只能证明兼容，可能共享错误 | 同源对齐＋独立核验样例；历法与紫微算法真值分开 |
| 本地排盘代表资料不会离开本地 | 根／子模型和 trace 仍可能接收出生资料 | 从产品入口检查模型与日志的资料处理，不只检查计算 Tool |
| 不建档案表等于不保存出生信息 | Journal、handoff、checkpoint 已持久化 | 明确现有保存事实，不默认写长期 Memory，不静默改变保存基线 |
| 可复现意味着预测可信 | 只证明同规则得到同盘，不验证命理解释 | 用户输出区分事实／传统解释／不确定性 |

上述修正的代码依据见主文档第 3、7、8、10 节；外部引擎依据见第 9 节。

## 3. 决议清单

本节所有条目状态均为 Proposed。推荐项可以用于安排验证工作，不等同于用户批准发布。

### ADR-7-01：领域边界与接入方式

- 决议建议：一个 `ziwei_doushu_agent`，通过现有受治理 Agent Delegation 接入根会话。
- 计算由确定性 Service 完成，LLM 负责工具选择与有依据的传统解释。
- 保留现有运行时、金融 Agent ID 和 API 入口；不引入独立命理 Agent SDK 或通用插件层。
- 代价：需要补齐共享委派基础设施，并回归已有金融功能。
- 批准节点：Stage 7 实施范围确认。

### ADR-7-02：五个工具与单一计算服务

- 决议建议：本命、大限、流年、流月、流日五个模型可见门面，内部统一生成一致快照。
- 出生资料由 child state 注入；服务纯函数语义显式接收所有输入，不依赖共享“当前命盘”。
- 不默认增加第六个回读工具；若预算实验表明必需，提交范围变更。
- 代价：需要规范化层级与投影模型，不能直接透传第三方库对象。
- 批准节点：Stage 7A 契约评审。

### ADR-7-03：引擎与默认规则

- 决议建议：先验证本地 `iztro`／`x-iztro` 候选及用户指定基准，再选定一个一期实现。
- 待用户回答：有无指定对齐的排盘来源；默认民用时间或真太阳时。
- 待验证：年界、日界、闰月、流派／四化表、大限年龄、历史时区和实际支持范围。
- 不采用“多引擎多数投票”；引擎差异必须解释规则来源。
- 批准节点：Stage 7A 结束前；未批准不能冻结默认 Convention 或接入真实资料灰度。

### ADR-7-04：时间目标和完整覆盖

- 决议建议：区分时点与历法区间，固定 Turn 的请求时间，按实际边界拆分目标区间。
- “今年”使用用户查询时区和可信 request_clock，不使用子任务执行机器当前时间。
- 不用年初／月中一个代表日的盘声称覆盖整个年份／月份。
- 代价：结果为 bundle＋segments，而不是所有查询都能返回一张单盘。
- 批准节点：Stage 7A DTO 与样例评审。

### ADR-7-05：澄清与结构化结果

- 决议建议：缺信息返回领域 outcome，根会话发问；一期不新增 Agent-child HITL 恢复。
- ReAct 取证后用独立 finalization 校验，真正的 Chart 引用由代码装配。
- 结构化方法以已部署模型兼容性验证为准，不能默认所有供应商支持同一种模式。
- 代价：补充资料产生新委派，而不是继续原 child run；finalization 增加有界调用成本。
- 批准节点：Stage 7B 联调前。

### ADR-7-06：执行快照、版本与恢复授权

- 决议建议：在既有委派记录持久化服务端快照，固定真实 graph／Tool／规则发布绑定。
- 原有 v1 载荷继续可读；新增 v2 必须按 Schema 版本路由。
- 去除 `*` 恢复兜底；新旧发布不能通过相同 graph 名称静默替换正在进行的任务。
- 需要同时验证父恢复交付窗口与并发 status，不能宣称数据库中有记录就已 exactly-once。
- 代价：数据库迁移、恢复逻辑与发布保留／排空策略；属于上线前必须满足的安全条件。
- 批准节点：Stage 7B 实施评审；没有安全替代方案时不得以延期修复方式上线。

### ADR-7-07：出生资料持久化与长期记忆

- 决议建议：一期不建长期出生档案，不将出生资料和命理解读写入长期 Memory。
- Journal、委派、Checkpoint、Artifact 继续按现有政策保存；向用户说明这一事实。
- 本阶段不变更原始会话永久保存和独立审计保留政策。
- 若产品希望短期保留或主动“忘记出生资料”，另行定义跨存储、外部 trace 与备份的生命周期。
- 代价：跨会话复用出生资料需要未来显式功能，不默认从长期 Memory 猜测。
- 批准节点：Stage 7 范围确认；真实资料灰度前确认用户告知内容。

### ADR-7-08：开发完整 I/O 的 confidential 例外

- 决议建议：对于含真实出生资料的 confidential 内容，开发环境也不输出完整原文到 trace／日志；
  完整调试仅使用合成或充分去标识样例。
- 与现有“开发环境完整 I/O”冻结决议存在明确例外，必须批准后更新安全／观测基线。
- 在批准前保持现有代码行为，但不以真实个人资料开展 Stage 7 开发测试。
- BFF 和 Agent Server 均需配置保护；模型请求数据处理不能靠 trace 隐藏选项替代。
- 批准节点：真实资料测试前。

### ADR-7-09：文本优先、功能收敛

- 决议建议：一期支持文本和结构化盘面、单对象、五个层级；不做图形盘、合盘、流时、择吉或自动追踪。
- 代价：用户不能一期获得可交互的十二宫可视化；可后续复用标准快照单独实现。
- 批准节点：Stage 7 范围确认。

## 4. 风险分级与发布阻断

| 级别 | 问题 | 解除条件 |
|---|---|---|
| P0 | 恢复扩权或跨对象／跨租户资料串用 | 快照与 ownership／scope 故障测试通过 |
| P0 | 盘面规则不明、关键时间边界错误 | 基准与 Convention 批准，边界黄金样例通过 |
| P0 | 实际 graph／Tool／引擎与记录版本不符 | 发布绑定与旧运行恢复验证通过 |
| P0 | 截断证据后仍输出完整解读 | 字节＋token 预算测试、覆盖校验和失败分支通过 |
| P0 | 真实资料进入不符合策略的模型／trace／日志 | 入口至子任务完整处理策略和配置验收 |
| P1 | 澄清卡住、structured result 丢失 | 新 Turn 澄清闭环和最终 state 提取通过 |
| P1 | 并发轮询或进程退出造成重复父恢复 | 并发／故障窗口对账测试通过 |
| P1 | 请求跨历法区间却只分析一个代表日 | 区间拆段与覆盖断言通过 |
| P2 | 输出偏长、重复调用、响应时间高 | 发布评测中的可配置预算与体验阈值达标 |

P0、P1 都是对应正式功能的发布门禁，分级不意味着可以忽略 P1。
不把与本地排盘无关的 MCP 远端重试缺口、通用调度改造或大规模合规平台建设夹带进一期。

## 5. 本轮交付及后续审批方式

本轮仅交付 Stage 7 设计、过程审视与文档导航；未修改业务代码、数据库或依赖。
下一轮可以先进行 Stage 7A 验证，不以未答复问题阻止原型和纯服务测试。

在开始各阶段实现时，将对应 ADR 更新为 Accepted／Rejected／Superseded，并记录日期、决定者、
最终选项与验证证据；设计稿的 Proposed 状态不能自动转成 Accepted。

最先需要用户确认的是排盘对齐来源和默认时间口径。其余具体规则先整理候选差异与样例，
再围绕实际会影响结果的分歧提问，不让用户在缺少验证材料时一次性选择所有底层参数。
