# Stage 10 架构决议

1. 业务 FastAPI 挂载到 AgentServer `http.app`，API 核心通过进程内 SDK 调用原生能力。
2. 一个镜像分 api、worker、integrations 三个角色；原生 queue 是唯一图执行队列。
3. `turn_id` 是唯一业务任务身份，start/resume 分别使用不可变 command，真实 native_run_id 只作为内部回执。
4. 运行持久化只保留 Turn、Command、Interaction；全库 14 表。未上线项目直接维护空库初始迁移。
5. prepared 可提交；sending/uncertain 永不自动重发，只查找原回执。租约不能重置发送权。
6. 最终状态需要当前 native run 与 checkpoint 证明，Journal、审计、通知与索引意图同事务。
7. SSE 是最新产品快照，LISTEN 只是提示；无客户端也必须收尾。
8. 人工交互绑定完整 checkpoint、interrupt、版本和动作；拒绝后封闭后续写动作，预算跨恢复累计。
9. 普通用户的原生资源默认拒绝；integrations 仅访问渠道入口和受限 Store。checkpoint 回收需独立产品维护 scope。
10. Stage 9 的上下文、记忆、归档、Manifest 与 outbox 语义继续成立；无兼容导入、旧接口别名或独立 BFF HTTP 进程。

具体约束见 [Stage 10 实施方案](stages/stage-10-统一API与运行模型收敛实施方案.md)。
