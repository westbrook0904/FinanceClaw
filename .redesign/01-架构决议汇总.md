# Stage 11 架构决议

> 适用范围：重构阶段的设计汇总，保留当时决议；当前实现与操作请阅读[包结构与请求链路](../docs/architecture/request-lifecycle.md)，其他历史记录见[档案索引](README.md)。

1. 业务 FastAPI 挂载到 AgentServer `http.app`，API 核心通过进程内 SDK 调用原生能力。
2. 一个镜像分 api、worker、integrations、memory_worker 四个角色；原生 queue 是唯一图执行队列，记忆工作由现有 Outbox 独立调度。
3. `turn_id` 是唯一业务任务身份，start/resume 分别使用不可变 command，真实 native_run_id 只作为内部回执。
4. 运行持久化保留 Turn、Command、Interaction；增加四张记忆表后全库 18 表。未上线项目直接维护空库初始迁移。
5. prepared 可提交；sending/uncertain 永不自动重发，只查找原回执。租约不能重置发送权。
6. 最终状态需要当前 native run 与 checkpoint 证明，Journal、审计、通知与索引意图同事务。
7. SSE 是最新产品快照，LISTEN 只是提示；无客户端也必须收尾。
8. 人工交互绑定完整 checkpoint、interrupt、版本和动作；拒绝后封闭后续写动作，预算跨恢复累计。
9. 普通用户的原生资源默认拒绝；integrations 仅访问渠道入口和受限 Store。checkpoint 回收需独立产品维护 scope。
10. checkpoint 管理 WorkingContext，应用 SQL 管理记忆权威，Store 管理可重建检索索引；画像按轮冻结，历史按需查询，完整工具中段可归档后压缩。
11. API、工具与后台共用记忆领域入口，候选确认独立于业务 interrupt；永久回执、source 顺序、版本 CAS、隐私屏障与有限派生许可阻止旧值复活。
12. memory_worker 使用有限权限的独立数据库身份和模型凭据，不接收应用管理员、产品、渠道或 Store 凭据。

具体约束见 [Stage 11 实施方案](stages/stage-11-异步记忆与上下文治理实施方案.md)，运行模型继续遵循 [Stage 10](stages/stage-10-统一API与运行模型收敛实施方案.md)。
