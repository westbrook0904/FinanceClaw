# FinanceClaw 安全、观测与评测设计

## 1. 安全边界

```text
Public Client
  → FinanceClaw API/BFF
      → internal Agent Server
          → Models / MCP / Financial Services
```

FinanceClaw API 是唯一公网入口和业务授权点。Agent Server 不直接暴露给最终用户。

## 2. Authentication 与 ExecutionContext

API 使用 OIDC/JWT 或企业 IdP 验证身份，构造可信 `ExecutionContext`。tenant、subject 和 scope 必须来自验证后的 Token/服务端映射，不能信任 body、Prompt 或模型生成值。

Agent Server 使用内网 service auth。部署能力允许时，额外使用 Agent Server custom auth/resource filter 作为防御层；它不替代 BFF 的业务授权。

## 3. Tenant Isolation

- 所有业务表携带 tenant_id；
- Conversation 与 Agent Server thread 保存所有权映射；
- Store namespace 包含 tenant/subject；
- Tool 查询在访问数据前绑定 scope；
- 向量检索在数据库查询内过滤 tenant/subject；
- 可选 PostgreSQL RLS 作为额外防御；
- 跨 tenant 测试是发布阻断项。

## 4. Tool Authorization

授权与指令约束分三道：

1. 模型调用前按 identity、tenant、AgentProfile、egress 和 data classification 过滤可见 Tool；
2. slash 指令只在过滤后的集合中约束目标，并在参数不完整时禁止本轮 Tool 执行；
3. Tool 执行前重新计算 PolicyDecision，同时复验指令目标、参数 hash 和 slot 完整性，不能依赖模型遵守 Prompt。

Policy 输出只有：

```text
ALLOW
DENY
REQUIRE_APPROVAL
```

LLM Tool Selector 只能在已授权集合内做相关性选择，不能参与权限决策。

WRITE Tool 默认不可重试；只有显式声明幂等、具有稳定 idempotency key 且异常可安全重试时才允许框架 retry。

## 5. Credential

Service Credential 存放在 Secret Manager、Vault 或 Kubernetes Secret。Delegated User Credential 使用 runtime credential handle；实际 Token 不进入模型、State、Journal、Memory、LangSmith metadata 或日志。

Debug 完整 Prompt 也不得包含 API Key、Authorization Header、Cookie、broker token 或数据库 DSN。

## 6. Data Egress

模型和外部 Tool 调用前统一验证：

```text
ExecutionContext.data_classification
ModelProfile.allowed_data_classes/regions
ToolGovernance.egress/sensitivity
tenant policy
```

Remote MCP 的 name/description/schema 不具备治理权威；side effect、approval、egress 和 retry profile 必须由本地配置覆盖。

## 7. LangSmith 调用链

LangSmith 是 LLM 应用主观测面。推荐根 Trace：

```text
turn/run
├─ context.prepare
│  ├─ conversation.recall
│  ├─ summary.retrieve
│  └─ memory.recall
├─ agent/workflow
│  ├─ model.call
│  ├─ tool.authorization
│  ├─ tool.call
│  └─ response.finalize
├─ conversation.persist
└─ audit.persist
```

LangChain/LangGraph 自动生成 Agent、Model 和 Tool runs；Context、Memory、Policy、Summary 等领域步骤使用少量 `@traceable` 补充，不建设自研 Tracer。

Metadata/Tags 至少包含：environment、run/thread/turn IDs、agent/workflow/model/profile versions、toolset version、risk level 和不可逆 tenant/subject hash。

## 8. 环境观测策略

### Development

- LangSmith 100% tracing；
- 完整 Prompt、messages、Tool Schema、response format；
- 完整模型可见输出与 Tool I/O；
- 本地 Debug Log 同步输出；
- 不记录 Secret 和隐藏推理。

### Staging

- 100% tracing；
- 默认脱敏敏感字段；
- 用于回归、压测和故障演练。

### Production

- 高风险金融 Workflow 100% trace；
- 普通请求可采样；
- 按 tenant/data class 条件隐藏或脱敏 inputs/outputs；
- Trace retention 不承担永久归档职责。

生产启动时若开发级完整 I/O 开关误开，应 fail fast 或强制关闭。

## 9. OpenTelemetry 与日志

OpenTelemetry 覆盖 FastAPI、PostgreSQL、Redis、外部 HTTP 和系统指标；用 run_id 与 LangSmith Trace 关联。结构化 Application Log 用于运维，允许轮转和删除。

不再保留自研 Span、TraceEvent、InMemoryTracer、ConsoleTracer 或 InMemoryEventBus。

## 10. Financial Audit

以下事件必须永久写 AuditRepository：

- ToolAllowed/Denied；
- ToolApprovalRequested/Approved/Rejected；
- FinancialToolExecuted；
- MemoryProposed/Committed/Superseded/Revoked/Deleted；
- WorkflowStarted/Completed/Failed；
- 关键数据 egress 决策。

Audit 保存结构化决策、版本、evidence、hash 和 Artifact reference，不复制 Secret、隐藏推理或无界 Provider payload。

## 11. Evaluation

### 11.1 pytest

覆盖确定性领域逻辑、Tool Contract、Graph、API、数据库、幂等、approval、tenant isolation 和故障恢复。

### 11.2 LangSmith Dataset/Experiment

至少建立：

- tool-selection；
- tool-arguments；
- financial-grounding；
- memory-recall；
- history-summarization；
- policy-refusal；
- approval；
- workflow-completion。

优先使用确定性 Evaluator；主观质量使用带明确 rubric 的 LLM-as-judge。

### 11.3 CI Gate

Prompt、AgentProfile、ModelProfile、Tool Schema/Description、Middleware、Summary、Memory recall、Workflow 或模型版本变化时必须运行回归。

阻断条件：

```text
Policy violation > 0
cross-tenant leakage > 0
unapproved WRITE execution > 0
stale financial fact treated as current > 0
critical workflow success regression
cost/latency beyond agreed threshold
```

每个 Experiment 记录 git commit、dataset、agent/workflow/model/prompt/toolset 版本。

## 12. Production Checklist

- Agent Server license/cost/data residency 已批准；
- LangSmith SaaS/self-host 方案已完成安全评审；
- Secret rotation、backup、restore、DR 演练通过；
- PostgreSQL/Redis/Artifact encryption 与访问策略完成；
- 数据删除流程覆盖业务库、Agent Server、Artifact 和 LangSmith；
- 高风险 Tool/Workflow 审批与 Audit 可回放；
- Debug I/O 开关在生产受保护；
- LangSmith 与基础设施告警已配置；
- 发布前 LangSmith Regression 通过。
